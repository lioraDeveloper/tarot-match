# כספת תוכן (Content Vault) — מבנה הפרדה למתכנת

המטרה: מתכנת יכול לבנות את האפליקציה **בלי לגשת לחומר הלימוד הסודי**  
(משמעויות קלפים מהספר, מסרים, מסלול ירוק, חוברת לימוד).

---

## תמונה כללית — 3 שכבות בתוך הכספת

```
content/vault/
  source/      ← חומר ספר / לימוד — הסוכן לומד מכאן. לא נכנס לאפליקציה
  drafts/      ← אופציות וניסויים (הרבה גרסאות). לא נכנס לאפליקציה
  published/   ← מסר אחד ברור + מסלול ירוק שנעול. האפליקציה טוענת רק מכאן
```

| שכבה | בשביל מה | מי נוגע | נכנס לקליק? |
|------|----------|---------|-------------|
| source | להבין לפי הספר | את + סוכן | לא |
| drafts | לשמור הרבה אופציות עד שמחליטים | את + סוכן | לא |
| published | המוצר החי | רק אחרי «נעול» | כן |

**כלל לסוכן:**  
מידע להבנה → `source/` · הצעות → `drafts/` · שינוי מוצר → רק אחרי שאת אומרת נעול ל־`published/`.

```
┌─────────────────────────────┐     ┌──────────────────────────────┐
│  ריפו קוד (בטוח למתכנת)      │     │  כספת תוכן (רק את)            │
│  app/  static/  tests/       │ ←── │  content/vault/{source,drafts,published} │
│  content/schema/             │     │  או ריפו פרטי / CMS           │
│  content/samples/ (דummies)  │     │                              │
└─────────────────────────────┘     └──────────────────────────────┘
```

האפליקציה יודעת רק את **צורת הנתונים** (schema) וטוענת מ־`published/` (או samples אצל מתכנת).


---

## מה סודי (לא לתת למתכנת)

| פריט | איפה עכשיו |
|------|------------|
| חוברת לימוד מהספר | `content/vault/source/` |
| הוראות קריאה מלאות | `content/vault/source/` |
| אופציות / ניסויים | `content/vault/drafts/` |
| מסר קצר + מסלול ירוק חיים | `content/vault/published/` |
| שלד קלפים בקוד | `app/tarot.py` (בלי טקסט סודי) |

## מה מותר למתכנת

| פריט | למה זה בסדר |
|------|-------------|
| מסכים, PWA, התחברות, צ׳אט, התאמות | קוד מוצר |
| API: «תן match → קבל 3 כרטיסים + טקסטים» | בלי לדעת מאיפה הטקסט בא |
| `content/schema/card-content.schema.json` | מבנה שדות בלי תוכן |
| `content/samples/*.json` | טקסט מזויף לפיתוח |
| שמות קלפים באנגלית / מזהים 0–21 | ידע כללי, לא הספר שלך |
| עיצוב, אנימציה, התקנה | לא IP של התוכן |

## 3 דרכים מומלצות (מהחזקה לפשוטה)

### א. ריפו תוכן נפרד (הכי נקי)
1. ריפו `tarot-match` = קוד בלבד → למתכנת.
2. ריפו פרטי `aether-content-vault` = רק שלך.
3. בשרת הייצור: מושכים תוכן מהכספת ב־deploy / משתני סביבה.
4. אצל המתכנת: רק `samples/`.

### ב. תיקיית vault בגיט־איגנור
1. `content/vault/` אצלך מקומית / בשרת.
2. ב־`.gitignore` — לא נשלח למתכנת.
3. ב־CI שלך: מעתיקים vault לפני הרצה.

### ג. CMS / אדמין רק שלך
1. מכניסה מסרים באדמין מוגן בסיסמה.
2. האפליקציה קוראת API של תוכן.
3. המתכנת בונה את האדמין הריק + המסכים — לא רואה את הרשומות האמיתיות (או רואה רק בסביבת staging עם דummies).

**המלצה לסטארטאפ שלך עכשיו:** א + samples.  
כשיגדל — להוסיף ג (CMS).

## איך האפליקציה צריכה להיראות למתכנת

```text
GET /api/union-spread
→ {
    cards: [{ id, name, position, love }],   // love = מסר קצר מוכן
    message: "...",                          // משפט מערכת
    green_path: { title, items: [...] }      // כבר מורכב בשרת
  }
```

המתכנת **מציג** את זה.  
הוא לא צריך את חוברת הספר כדי לבנות UI.

הלוגיקה «איך בונים green_path מקלף» נשארת אצלך / בשרת עם vault.
